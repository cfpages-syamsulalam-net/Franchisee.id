## Why this repository had to change

Premium activation is `handleReviewPremiumPayment` in `functions/_dashboard-actions.js`. At the publication-row insert (around line 711–727) it calls `premiumCanonicalUrl(siteId, confirmation.slug)` for each of `PREMIUM_NETWORK_SITE_IDS` and writes the result into `franchise_site_publications.canonical_url`. Whichever dashboard runs the approval therefore decides the canonical URL for all four sites. With the previous single-format helper, an approval run from Franchisee.id's dashboard would write `/peluang-usaha/{slug}/` into the franchisor row.

Evidence for the new value: franchisor.id serves real brand pages at `/usaha/{slug}` and those pages declare that URL as their own `<link rel="canonical">` (verified anonymously 2026-09-25: `/usaha/codero` returns 322,496 bytes with `canonical='/usaha/codero'`). The `/peluang-usaha/{slug}` form on that domain returns the site's soft-404 catch-all — HTTP 200 with the same 333,814-byte directory home page that `/this-does-not-exist-12345/` returns.

## Follow-up in the same session — shared-platform review fixes (`0498f62`)

An independent review of the Franchisor.id Gate 1 port found four shared defects that also live here. All four are fixed in `0498f62`, mirroring `Franchisor.id` `02f486d`:

1. The review-approval schema enumerated listing fields only, so a `franchisor_profile` proposal could never be approved — the client posts `profile_*` names and zod rejected them before the handler ran. One allowlist is now built from `OWNER_PROFILE_FIELDS` (with `pic_name` and `email_contact` added) plus `EDITABLE_LISTING_FIELD_DEFS`.
2. `update_account` wrote `franchisor_profiles.pic_name`/`email_contact` directly, so a display-name save could replace a published brand's public contact. Account identity now applies immediately while a published brand's contact becomes an owner review proposal.
3. The claim queue shipped claimant NIB, HAKI, and contact fields to staff although claim decisions are admin-only. The whole queue is now `isAdmin(auth)`-gated, as the new-brand queue already was.
4. The claim path inserted `franchisor_profiles` unconditionally, so an unavailable claim committed an orphan profile. The insert now shares the claimability predicate.

**A defect introduced and caught here.** A TypeScript `as` cast was briefly placed in the JavaScript file `functions/_dashboard-schemas.js`, which esbuild cannot transform. Franchisor.id's suite did not notice because nothing in it transformed that module; this repository's `functions:methods:check`, `google-contacts:check`, `ocr:check`, and `ocr:runner:check` failed immediately, which is how it was found and removed in both repositories. Worth remembering as evidence that cross-repo checks catch what a single repository's suite cannot.
